# 求职者视角的产品分析与需求

分析日期：2026-10-09（北京时间）。状态：需求建议，尚未实施；本文不代表已经完成的功能或已经确定的开发排期。

本文面向本人当前的求职任务：2027 届，准备 AI Agent、LLM 应用与相关后端岗位，已有 VendorGuard 和发票识别实习经历。结论来自项目状态、相关源码及本次 HTTP 服务端输出核对，没有进行用户访谈、学习效果实验或本轮浏览器点击验收。

## 1. 产品判断

项目已经能可靠地组织练习、保存作答、恢复中断和安排复习。下一步应帮助求职者完成四件事：选对当前需要准备的内容，把参考思路变成自己的真实回答，承接项目追问，以及看清还有哪些面试风险。

现阶段最大的缺口是题库内容与求职过程之间的连接。题库已经有 670 题，其中 100 道简历专项题附带 300 个追问；但首页的新题推荐仍围绕原来的 30 道核心题，简历主线需要自己搜索。练过多少次、自评是否掌握，也不能直接回答“我能不能把项目讲清楚”。

建议下一期优先完成“选题 → 独立表达 → 对照漏点 → 保存个人回答 → 再练”的流程。继续扩题、自动 AI 评分和云端账户的收益，应在这条流程能日常使用之后评估。

### R01：让我直接进入简历主线

**用户需求：**我想从自己的项目和实习开始准备，不想先了解整个题库的组织方式。

**首版范围：**首页提供“简历重点”“项目讲述”“基础补齐”入口；题库和练习设置提供专题、项目、内容优先级、回答性质筛选。项目至少支持 VendorGuard、发票实习和综合讲述。展示范围题数，并支持从筛选结果开始一轮练习。

已有标签与结构化简历内容足够支持首版，不需要先做自动简历解析。优先级与难度分别展示；“扩展设计”明确按假设方案回答，不能混成已完成经历。

**验收标准：**

- 从首页进入简历重点并开始一轮，最多两次主要操作，不需要手输“简历 P0”。
- 选择“简历专项 + VendorGuard + P0”后，列表、范围题数和新一轮队列采用相同筛选口径；队列不混入其他项目题。
- 当前简历题整体范围为 100 题，P0 为 63 题；以启用题实时统计，后续内容变化时不硬编码这些数量。
- 筛选条件保存在 URL，返回列表仍保留条件；没有匹配题时说明原因，可直接调整筛选。
- 更改下一轮设置不改变已经开始的固定队列；原有继续练习仍可用。

### R02：让我在有限时间里推进目标

**用户需求：**我每天只有一小段时间，希望重点能持续推进，也希望面试临近时知道如何缩小范围。

**首版范围：**提供可选的岗位方向、当前训练路径、每日可用时间和面试日期设置。先提供“通用核心”“简历重点”“项目讲述”等预设，允许不配置直接使用；支持 3 / 5 题短轮，保留 10 / 20 题。

今日推荐的新题可来自选定路径。默认继续采用到期复习 → 正式练过的薄弱题 → 路径新题，显示每题入选理由。路径外的到期题单独提示数量和入口；不让它们在用户不知情时占满目标路径的一轮。冲刺模式由用户主动选择，优先展示所选目标中的重点卡点和未覆盖内容。

每日分钟数先用于选择训练规模，不把“5 道题”宣称成精确的“15 分钟”。面试日期用于提示时间和切换冲刺视图，不声称系统能据此保证完成准备。

**验收标准：**

- 选择简历重点后，尚未正式练过的简历重点题可作为新题推荐；未配置的用户仍能按原通用路径使用。
- 开始前能看到本轮范围、实际题数、推荐来源；明确区分“只有两道符合条件”与“已全部准备完成”。
- 默认去重，并继续排除北京时间当天已正式完成的题；用户主动重练不受该自动推荐规则限制。
- 3 / 5 题轮次也支持草稿、刷新续练、提前结束和总结；中途改目标不改变本轮队列。
- 保存、修改目标不产生练习事件或掌握记录；面试日期可为空或修改。

### R03：让我先学会短答，再查细节

**用户需求：**我需要面试时能讲出来的主线，而不是每道题先阅读一大篇答案。

**首版范围：**把简历题已有的短答、三个要点、来源、场景、追问、易错点和资料用于分层展示。练习先展示问题；主动展开参考后优先显示 60–90 秒回答思路与要点，其余按需展开。详情页提供相同层次，方便查阅。

**验收标准：**

- 独立作答阶段不默认泄露参考答案；展开后可先读短答和要点，无需翻完全部章节。
- 简历来源、实战 / 基础 / 扩展性质和关键能力边界容易找到；折叠不造成把假设误当履历事实。
- 页面短答与完整答案来自同一份结构化内容；原有深度内容和资料不丢失。
- 原来的核心 30 题仍按现有分层展示；未结构化的普通题继续可读。

### R04：让我留下自己的真实回答

**用户需求：**参考答案只是帮助。我想记录自己做了什么、怎么判断、有什么证据，然后反复练这套表达。

**首版范围：**每题维护一张可编辑的个人回答卡，包含“我的短答”和可选的“真实例子 / 个人贡献与边界 / 证据位置”。可以把某次文字回答复制到卡片后修改，也可以只记一句漏点。证据先记录本人填写的脱敏描述、文件位置或链接，不自动读取其他项目。

个人卡长期保存，区别于本轮草稿、正式作答历史和公共参考答案。口头作答仍允许不输入全文，可在结束后简记自己的表达或卡点，不把填写整张卡设为完成练习的前置条件。

**验收标准：**

- 保存后刷新、开启新一轮、重启应用仍能读到个人卡；不依赖单个浏览器草稿长期保管。
- 修改个人卡不增加练习次数、不改变自评与复习时间，也不覆写历史回答。
- 从历史回答创建卡片后，两者仍各自保留；题库重新导入不会把个人卡替换成种子内容。
- 独立练习时个人卡也不默认展示；用户可主动查看，避免变成照稿完成。
- 尚未准备证据时允许留空；界面不自动补造业务收益、个人贡献或实现细节。

### R05：让我知道为什么答不好

**用户需求：**“模糊”太笼统。我想知道是概念不清、表达不顺、缺少例子，还是追问答不出来。

**首版范围：**对照参考后，用本题已有的三个要点检查自己是否覆盖，允许记录“漏了哪个点”。可多选卡点原因：概念不清、表达卡壳、缺少项目证据、追问不会、其他；其他允许简短说明。总结提供“下次练什么”和从本轮卡点开启小轮的入口。

要点勾选是用户自查，不是系统客观评分。保留现有不会 / 模糊 / 掌握语义和正式完成流程，检查与记录尽量轻量，不要求每次填写全部字段。

**验收标准：**

- 能把具体漏点关联到题目及对应作答；历史保留当时的检查结果，后续修改个人卡不会改写它。
- “缺证据”和“机制不会”能分别查找并补练，不能都只剩一个“薄弱”状态。
- 选择漏点、修改说明、编辑回答卡不生成新的正式完成；正式提交仍保持幂等。
- 口头且未转写的回答可由本人自查，但不显示“系统已核验”或客观得分。
- 补练仍采用固定队列、题目隔离草稿和失败恢复，不丢失尚未完成的内容。

### R06：让我接受连续追问

**用户需求：**我想试一次接近面试的过程，确认自己能否在不看答案时讲清项目并继续解释。

**首版范围：**提供固定脚本的项目模拟：自我介绍或职责 → 项目主问题 → 逐个追问 → 相关基础。先使用已有简历题的追问，可选练 VendorGuard 或发票实习；逐个展示、可计时、允许跳过或中止，结束后统一看参考与复盘。

先支持口头回答加简短记录，以及文字回答；不把录音、转写或动态 AI 面试官作为首版前提。计时表示作答过程，不据此自动推断答得对或已经完成。

**验收标准：**

- 至少能完成一个主问题及其三个已有追问，回答期间不展示后续参考内容。
- 明确标记主问题与追问关系，每个节点有自己的记录；中断后能继续，不乱序。
- 三个追问不会暗中给原题增加三次完成；模拟轮次、节点记录与普通题完成的统计口径分别说明，正式完成仍需明确动作。
- 总结列出未答、表达卡点、需补证据和建议关联基础，不把没有文字的口头表现当作自动评分证据。

### R07：让我看清目标范围内的准备缺口

**用户需求：**我不需要把 670 道全部刷完。我需要知道当前目标的重点还有哪些没有讲过、哪些总是卡住。

**首版范围：**按当前路径显示正式练习覆盖、自评分布、未练重点、卡点和缺证据题；允许比较同题旧回答与新回答。首期先显示范围题数、正式练过题数和未练列表，详细变化统计在积累 R05 记录后再做。

**验收标准：**

- 覆盖率分母是当前目标的启用题数，分子是其中至少有一次正式练习的独立题数；重复完成不扩大覆盖。
- 仅修改状态不能进入“正式练过”；旧版标记记录也不能被当作新的正式作答。
- 目标切换后说明统计范围；已有回答与进度保留。空范围或无记录显示明确空状态。
- 自评掌握、正式覆盖、已有个人卡、本人认为证据齐全分别呈现，不合并成“面试通过率”。
- 无旧回答或口头未留内容时说明无法比较；没有卡点历史时不编造“持续改善”趋势。

### R08：让我把真实面试转成下一次训练

**用户需求：**面试结束后，我想趁还记得，记录当时的问题、回答和失误，然后补上。

**首版范围：**记录日期、岗位或面试名称、实际问题、自己的回答摘要、卡点和改进。支持关联已有题，也允许先保存题库里没有的问题。复盘中的问题可加入个人补练清单。

这里的职责是面试学习复盘，不扩成投递管理、企业招聘系统或 Offer 管理。

**验收标准：**

- 只有一个新问题也能保存；关联题不自动标成已经练过或掌握。
- 对已有题，一键进入补练并继承它的参考内容；对未收录题，可以先训练本人记录的问题，不自动冒充已有标准答案。
- 多次面试记录彼此区分，能追溯问题来源；修改公共题内容不抹去当时原话。
- 同一题被多次面试问到时，可关联到多个复盘，不用复制出多道公共题。

### R09：让我更容易每天使用并保留积累

**用户需求：**我想打开就练，出了问题能理解怎么处理，也希望自己的答案和复盘可以备份带走。

**首版范围：**Windows 启动入口检查并复用现有数据库和应用，服务就绪后打开页面，失败时给出具体原因与日志位置。提供个人数据备份与可阅读导出，逐步覆盖进度、历史回答、个人卡、卡点、目标设置和复盘；附匹配版本的恢复方法。

**验收标准：**

- 已经运行时可直接打开，不重复占用端口；启动不能重新初始化个人库或自动清掉历史。
- 端口占用、数据库连接失败和应用启动失败能分别定位，不只显示“启动失败”。
- 备份说明包含创建时间、适用版本和包含的数据；在独立库恢复并核对内容后，才能称为可恢复备份。
- 可阅读导出说明它与数据库恢复备份的区别；仅有文本导出不能宣称已验证恢复。
- 个人数据默认留在本机，不要求先注册账户才能继续使用。

### R10：按实际需要引入 JD、AI 和语音

**用户需求：**基础流程用顺以后，我希望减少整理岗位重点、评价答案和记录口头回答的成本。

这三个方向分别评估，不打包成下一期的必做大功能：

| 方向        | 建议最小范围                                     | 引入条件与验收边界                                                                               |
| ----------- | ------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| JD 定向     | 保存 JD 与本人选择的技能主题，映射已有训练题     | 先解决多个岗位重点不同的实际问题；映射允许人工调整，不凭职位名推断所有能力                       |
| AI 辅助反馈 | 基于题目要点和本次实际回答指出遗漏，引用回答原文 | 明确是建议；不知道真实项目细节时提示待补证据，不自动提升自评或编造经历；失败后手工流程仍可用     |
| 录音与转写  | 用户主动录制，转写后可校对，关联到本次回答       | 先有明确的口头记录需要；显示录制状态与保存结果，转写失败仍能保存简记，不把转写质量等同于回答质量 |

登录、云同步、多人排行榜、商业化和复杂 Agent 编排当前不列为本人的近期优先需求。跨设备使用若成为经常发生的障碍，再单独提出部署、账户与数据同步要求。

## 5. 推荐交付顺序

## 6. 学习效果如何判断

验收首先检查功能正确与记录不丢，再用本人连续使用判断有没有帮助。当前没有建立学习效果基线，不给出“提升百分比”或面试成功概率。

| 问题             | 可观察依据                                             | 避免的误读                                   |
| ---------------- | ------------------------------------------------------ | -------------------------------------------- |
| 是否更容易开始   | 首页到开始目标练习的操作数；是否仍需要手输关键词       | 入口点击增加不等于知识提升                   |
| 是否覆盖目标     | 当前路径中有正式作答的独立题数、未练重点列表           | 累计次数不是覆盖题数，670 题不是必刷任务     |
| 是否形成个人表达 | 本人的短答、例子、贡献和证据说明；独立重答时是否能讲清 | 有卡片不等于已掌握，参考答案长度不是个人能力 |
| 是否减少相同失误 | 同题多次作答的具体漏点变化；是否能独立承接原追问       | 没留记录的口头回答无法客观比较               |
| 是否符合可用时间 | 短轮是否更容易完成或继续；用户记录的实际耗时与负担     | 题数不直接换算成固定分钟数                   |
| 是否承接真实面试 | 复盘中的问题是否有对应补练，下次表达是否改善           | 真实面试结果还受岗位、招聘流程等因素影响     |

首期使用反馈重点：本人是否更快开始、是否愿意留下个人答案、卡点记录是否过于繁琐，以及一轮 3–5 题是否符合实际时间。根据反馈调整字段和默认轮次，再决定是否需要 AI 或语音。

## 7. 实施时需要延续的契约

这些是已有项目能力的保护要求，不是新增审批流程：

- 保留题目 ID、历史事件和个人进度。种子按题干更新的身份规则不变；新需求确实需要身份变更时单独设计迁移。
- 新配置与个人卡持久化后不得被种子导入覆写。公共参考内容、长期个人答案、轮次草稿、正式回答和面试原始记录分开保存。
- 固定队列、题目隔离草稿、刷新续练、提前结束、`attemptId` 幂等、事务保存和成功响应丢失恢复继续有效。
- 自评标记、编辑笔记、填写卡点和打开页面不增加练习次数；计时结束、追问展示也不自动计原题完成。
- 默认推荐继续遵守北京时间日界线、去重和当天正式完成排除；目标范围变化与主动重练采用显式规则。
- 保留中文优先、长时间阅读、移动端、主题与键盘可用性。操作入口便捷，不把所有可选记录强制塞进每次完成流程。
- 实施后验证相关选题、持久化、恢复与统计契约；数据测试使用独立 PostgreSQL，个人库不创建验收假记录。
