## 使用流程

题目详情、逐次历史回答和轮次总结都提供“查看 / 编辑我的回答卡”。四项分别为我的短答、真实例子、我的贡献与边界、可出示的证据，默认空白，均可留空。从某次正式回答进入时，点击“把这次回答带入短答”才复制文字；不会自动覆盖卡片，也不把公共参考答案变成本人经历。保存卡片后，刷新、新轮和应用重启仍从数据库读取。

练习仍先独立回答；展开参考后才出现卡片入口与要点自查。简历题用三个结构化要点，核心题使用前三个要点，其他题可只记卡点。选择一个要点后明确填写“已覆盖 / 还欠缺”，可附说明；五类卡点可多选：概念不清、表达不顺、缺少项目证据、追问接不住、其他。每项说明最多 2000 字符。

可以独立保存，也可以在正式完成后关联当次回答。正式提交暂时失败或响应未确认时，自查继续保留为草稿，练习和总结均暂不允许保存关联；恢复服务器完成记录后再保存。总结可以打开本轮各题的自查草稿，卡点记录链接到对应的正式回答专页。保存自查后，详情和历史专页显示当时的要点与说明快照；公共答案后续变化时，旧草稿和已保存快照仍可读。

主导航新增 [卡点](http://localhost:3000/practice-gaps)。默认显示全部范围未解决记录，可按项目、预设、优先级、回答性质、卡点类型与解决状态筛选，也可主动使用当前训练目标范围。标为已解决与重新打开都是明确状态操作。补练按记录最早创建时间及 ID 排序、按题去重，提供 3/5 题档，显示实际题数并复用原固定队列。目标中途改变不改变本轮队列。

停用题的卡片、卡点、自查与历史详情保持可读，题库与补练仍跳过停用题。解决卡点只代表本人记录的状态；要点是本人自查，本批次没有自动评分。

## 数据与接口

复用 W0 已建表和严格校验，不改 Schema、不改写冻结迁移、不更新公共题。个人卡、观察和卡点不更新历史回答、掌握状态、练习次数或复习时间。

| 接口                                   | 行为                                                                                                                     |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `GET /api/answer-cards?questionId=...` | 本人卡片或 null；题不存在 404，非法/重复参数 400                                                                         |
| `PUT /api/answer-cards`                | 四字段 trim、单项最多 10000；新建 revision 1，正常更新 +1；落后仅一版且内容相同按重试返回 200，否则 409 附当前卡         |
| `POST /api/practice-observations`      | 严格校验最多 3 要点、5 类卡点、重复项及归属；父子记录事务保存，requestId 同规范化 payload 返回 200，异内容 409，新建 201 |
| `GET /api/practice-gaps`               | 共用范围查询，kind、resolved 筛选；默认未解决，`resolved=all` 查看全部                                                   |
| `PATCH /api/practice-gaps/[id]`        | `{resolved:boolean}`，重复解决保留首次时间；他人或不存在记录 404                                                         |

新建卡片与更新在事务中锁本人用户行，避免空记录首次并发绕过版本校验。观察使用唯一 requestId 和冲突后读取，避免并发重试重复子记录。关联事件必须属于 default、对应题目，且 `kind=practice`；仅依赖外键不足以证明正式完成。解决卡点不改父 payload，重试原观察不会重新打开。

卡片 409 保留本地编辑并显示服务端四字段，可对照合并后采用最新版本号，或主动替换为服务端内容。未保存卡片编辑和本轮自查使用有 schema 校验的浏览器草稿，保存后的长期数据在 PostgreSQL；请求失败保留原 requestId/payload。存储配额用尽时，页面内保留最新编辑并提示保持页面打开，不承诺关闭浏览器后的恢复。

核心位置：`src/lib/practice-notes.ts`、`practice-notes-contract.ts`、`note-draft.ts`，四组 API，新 `/questions/[id]/answer-card`、`/questions/[id]/history/[eventId]`、`/practice-gaps` 页面，以及个人卡/观察/卡点状态组件。`RoundCompletion` 新增可选 eventId，正式响应和服务端恢复均携带真实事件 ID，既有草稿与旧完成结构兼容。
