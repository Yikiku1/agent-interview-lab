## 3. 今日推荐的产品与选题规则

### 首页表现

首页主区域展示“今日推荐练习”、实际题数、题目来源组成、当前核心主题和“开始推荐练习”。例如：“10 题 · 到期复习 4 · 薄弱巩固 3 · 核心新题 3”。示例中的数量必须来自真实队列。

保留醒目的“继续练习”入口及手动练习设置入口。用户只浏览首页时保持原练习上下文；点击开始新一轮后，再更新当前浏览器的续练记录。

“今日推荐”是根据当前时间与进度生成的建议，不是每天额外增加 10 题的任务。队列不足 10 题时展示实际数量。

### 选题优先级

按以下顺序取题，合并后最多 10 题。每个问题 ID 只出现一次。

| 来源     | 范围与资格                                                                | 顺序                                                                         |
| -------- | ------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 到期复习 | 全部启用题；已有非空 `next_review_at`，且不晚于本次请求时间；包含已掌握题 | 到期时间升序；同一时间下不会优先、模糊其次、掌握最后；最终按题目 ID 稳定排序 |
| 薄弱巩固 | 全部启用题；至少完成过一次正式练习；最新状态为不会或模糊；排除已入选题    | 不会优先；最近一次正式完成时间较早者优先；最终按题目 ID 排序                 |
| 核心新题 | 30 道核心题中的启用题；从未产生 `kind=practice` 的完成事件                | 按核心训练路径顺序                                                           |

所有来源都排除北京时间当天已经正式完成过的题目，防止重新打开首页反复推荐刚完成的题。用户仍可通过手动练习主动重复训练。

几个定义必须保持明确：

- “正式完成”指 `review_events.kind=practice`；只标记状态、旧版 `legacy` 事件及打开页面均不算完成。
- `next_review_at=null` 表示尚未建立复习安排，不作为推荐中的“到期复习”。属于核心题且未正式完成时，可以进入核心新题。
- 现有手动到期模式包含“待首次练习”的行为继续兼容；推荐入口使用自己的明确规则，避免直接复用该模式造成来源误标。
- 当天区间按北京时间的 `[当天 00:00, 次日 00:00)` 计算。选题使用统一的请求时间，测试能注入固定时间。
- 首轮推荐可以跨主题补齐，但每道核心新题仍遵循路径顺序；首页展示实际涉及的主题。

30 道核心题都完成过且没有符合条件的到期题、薄弱题时，展示“暂无推荐题目”，附手动练习与题库入口。有当天完成记录时，可说明“今天已完成的题目已排除”。这不表示整个题库都已掌握。

### 开始、刷新与继续

首页展示的组成与点击后进入的队列必须一致。可以把已选 ID 放进现有 `queue` 参数，沿用 `round`、`questionId`、`finished` 的固定队列机制。

建议增加 `mode=daily` 表示推荐来源；涉及的模式类型、解析、界面文案和缺失队列时的处理必须一起更新。旧模式和旧续练链接继续可用。直接访问无队列的推荐链接时，只生成一次队列，再进入现有规范 URL。

开始后，无论状态改变、刷新、切题、午夜跨日或再次从首页继续，本轮都使用保存的队列和位置；只有明确开始新一轮才重新推荐。停用题目继续按现有规则跳过。点击前恰好有题目被停用时，以实际可用题数为准并明确反馈。

推荐计算和页面读取均不写入练习事件，也不调整复习安排。

## 4. 核心题训练路径与内容

当前已精修的 30 题分布为：LLM 5、Python 4、后端 3、数据库 3、RAG 5、LLM 应用工程 5、Agent 5。

默认路径为：**LLM → Python → 后端 → 数据库 → RAG → LLM 应用工程 → Agent**。同一主题内按现有核心题定义顺序排列。本期使用固定默认路径，路径编辑器及岗位配置留到后续。

当前主题取路径中首个仍有未正式完成题目的主题。进度显示“核心题已练 X / 30”，仅统计启用核心题，避免把“练过”表述为“掌握”。若核心题被停用，分母与当前主题按实际启用内容更新。

### 内容结构与单一来源

将 `src/db/core-answers.ts` 中的核心题整理为具名结构化条目，至少包含：

```ts
type CoreLearningEntry = {
  question: string;
  category: string;
  oral: string;
  keyPoints: readonly string[];
  explanation: string;
  example: string;
  pitfalls: readonly string[];
  followUps: readonly [string, string];
  projectPrompt: string;
  sources: readonly [label: string, url: string][];
};
```

继续从这份结构化数据生成种子使用的 `coreAnswers` Markdown，避免维护两份完整答案。保留 `learningAnswer` 与普通基础题的兼容接口；具体模块拆分可按实际依赖调整。

每题的质量要求：

- 3–5 条回答要点直接对应题干，能用来检查回答是否覆盖关键内容。
- 1–2 条误区必须指出具体错误及边界，例如“Schema 合法不等于资源访问已授权”。
- 项目提示引导用户解释自己真实做过的流程、取舍或验证，不预填个人经历。
- 保留现有短答、深入解释、代码或验证示例、两个追问和官方资料。
- 不增加题库总数、不批量改变难度，不用换题干的方式替换现有题目。

数据库题目 ID 由已有种子流程保留。运行时通过核心题的唯一题干映射数据库题目，沿用现有 `核心精修` 标记作辅助；路径与内容定义不硬编码本机数据库数字 ID。执行种子导入时沿用按题干更新的流程，保留进度和历史记录。

推荐模块只需读取核心题轻量顺序信息；练习页面仅向客户端传当前队列所需的结构化内容，避免把整份种子题库打包到首页或客户端。

## 5. 练习中的参考答案与自评

保持阅读顺序：**题干 → 我的回答 → 参考答案 → 自评与完成 → 切题**。

默认隐藏参考答案及回答要点，让用户先独立作答。展开后，核心题默认展示“30–60 秒回答”和回答要点；深入理解、最小示例与验证、常见误区、常见追问、项目举例提示、参考资料按需展开。

优先使用原生 `details/summary` 或现有可访问公共组件。展开按钮应有清晰标签、可见焦点和足够大的点击区域。代码块保持可横向滚动，手机页面整体不产生横向溢出。

切到另一题后，参考答案重新隐藏，内部展开状态重置。展开、折叠和切换主题不影响草稿、自评或提交状态。非核心题及没有结构化内容的题目继续完整显示原 Markdown 答案。

在自评区提供简短说明，必要的详细标准按需展开：

| 自评 | 标准                                                           |
| ---- | -------------------------------------------------------------- |
| 不会 | 无法独立形成关键思路，或主要结论明显错误                       |
| 模糊 | 能回答部分内容，但遗漏关键要点、需要提示，或无法解释例子与边界 |
| 掌握 | 不看答案能覆盖关键要点，用合理例子解释，并回答基础追问         |

回答要点是对照提示，本期无需新增必填勾选、评分字段或 AI 分数。最终状态仍由用户选择；仍支持口头作答和空白文字回答。仅选择自评不计次数，“完成本题”才提交回答并推进复习安排。

| 场景                                         | 预期                                                              |
| -------------------------------------------- | ----------------------------------------------------------------- |
| 到期、薄弱、新题混合，某题同时符合多个来源   | 优先级正确，每题唯一，组成统计等于实际队列                        |

| 开始推荐、切题、刷新、首页继续及提前总结     | 队列、位置、草稿、完成记录与总结保持一致                          |
